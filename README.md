# Pharmacy Management System

A complete, self-hosted pharmacy management system with a **React PWA frontend** and a **pure PHP 8.1+ REST API backend** on MySQL/MariaDB. It covers the full retail-pharmacy workflow: batch-aware inventory, purchases, point-of-sale, customers, suppliers, expenses, employees, prescriptions, reports, and PDF/Excel exports.

> **No Firebase, no Supabase, no backend-as-a-service.** The backend is plain PHP (PDO + MySQL) with JWT auth via `firebase/php-jwt` (a PHP JWT library — *not* Firebase backend services). Uploads live on the server's own filesystem under `storage/`; only paths are stored in the database. The whole stack runs on KSWEB (Android), XAMPP, WAMP, LAMP, shared PHP hosting, Apache, or Nginx + PHP-FPM.

## Features

### Auth & RBAC
- Login/logout with short-lived **JWT access tokens** and refresh via **httpOnly cookie**
- Password reset (forgot/reset), change password, profile + profile photo
- Role-based access control: users → roles → permissions (e.g. `medicines.create`, `sales.return`, `reports.export`)
- Users and roles management screens; permission catalog enforced server-side by middleware
- Rate limiting and audit logging of sensitive actions

### Dashboard
- KPI cards: today's sales, purchases, profit, low-stock count, expiring-soon count
- Sales/purchases charts (Recharts), recent transactions, top-selling medicines
- Quick alerts for low stock and near-expiry batches

### Medicines & Batches
- Medicine master records: name, generic, category, manufacturer, strength, pack size, units, prices, barcode/QR
- **Batch tracking**: batch number, expiry date, cost price, quantity per batch (FIFO-friendly)
- Categories and manufacturers management
- Barcode/QR code labels (print from the medicine view)

### Inventory
- Live stock levels per medicine and per batch
- Manual **stock adjustments** (damage, expiry write-off, corrections) with reason log
- **Stock transfers** between locations
- Stock valuation report
- **Low-stock alerts** and **expiring-soon alerts** with in-app notifications
- Full stock movement history per item

### Purchases
- Purchase orders/invoices to suppliers with per-item batch details
- Partial/full **supplier payments** tracking
- **Purchase returns** to supplier

### POS Sales
- Fast point-of-sale screen: barcode search, cart, per-item discount, tax
- Cash/card/credit payments; credit sales attach to customer accounts
- Thermal receipt printing; invoice PDF
- **Sales returns** with stock restock

### Customers
- Customer profiles with contact info and credit limits
- **Customer ledger** and printable **statement of account**

### Suppliers
- Supplier profiles
- **Supplier ledger** with purchase and payment history

### Expenses
- Expense entries with custom **expense categories**
- Attachments (receipts) stored under `storage/attachments/`

### Employees
- Employee records with photos under `storage/employees/`
- **Attendance** marking
- **Salary** processing
- **Leave** requests and approvals

### Prescriptions
- Prescription records linked to customers/sales, with scanned images under `storage/prescriptions/`

### Lab module (optional)
- The lab module is **disabled by default**. It can be enabled from Settings when the pharmacy also runs lab test booking. It ships with the same RBAC permission model.

### Reports
- Sales, purchases, profit, inventory, expiry, and expense reports
- Custom reports with `?from&to`, search, and pagination
- Date-range filters everywhere

### PDF / Excel export
- PDF exports via optional `dompdf/dompdf` (invoices, receipts, statements, reports)
- Excel exports via optional `phpoffice/phpspreadsheet`

### Notifications
- In-app notifications: low stock, near-expiry batches, generated by a scheduled CLI run (see `docs/INSTALLATION.md`)

### Settings
- Pharmacy profile (name, address, phone, logo under `storage/logos/`)
- Tax, currency, invoice numbering, lab module toggle, notification thresholds

### Audit logs
- Every create/update/delete and login is recorded with user, IP, and timestamp

### PWA / Offline
- Installable PWA (manifest + service worker) from `frontend/`
- Offline-tolerant: the shell and cached pages keep working when connectivity drops; API calls queue/error gracefully when offline

## Tech stack

| Layer | Technology |
|---|---|
| Frontend | React 18 + Vite, Tailwind CSS, Lucide React icons, Recharts |
| Frontend API client | `VITE_API_URL` base URL, Bearer JWT, cookie refresh |
| Backend | PHP 8.1+ (strict types), REST API, front controller `backend/index.php` |
| Backend libs | `firebase/php-jwt` (JWT only), optional `dompdf/dompdf`, optional `phpoffice/phpspreadsheet` |
| Database | MySQL 8+ / MariaDB (`database/schema.sql`, demo seed in `database/seed.sql`) |
| Auth | JWT access token (Bearer) + httpOnly refresh cookie, RBAC permissions |
| Uploads | Server filesystem under `storage/`; DB stores relative paths |
| Targets | KSWEB (Android), XAMPP, WAMP, LAMP, shared PHP hosting, Apache, Nginx + PHP-FPM |

---

**Architecture note:** there is no Firebase and no Supabase in this project — not as a database, not as auth, not as storage. The only package with "firebase" in its name is `firebase/php-jwt`, a PHP library for signing/verifying JSON Web Tokens locally. Authentication, the database, file uploads, and push/offline behavior are all implemented with plain PHP + MySQL + the browser.
